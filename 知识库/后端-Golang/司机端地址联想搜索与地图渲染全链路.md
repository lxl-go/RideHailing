# 司机端地址联想搜索与地图渲染：proto→服务→网关→前端 全链路新增

## 适用场景 / 问题背景

司机发布行程页只有纯文本输入，无地址联想下拉、无地图预览。需求：输入时弹出候选地点列表，选中后回填名称与经纬度，并在地图上标记起终点。本知识库记录「从 proto 加一个 RPC 到前端能用的完整链路」的标准动作。

## 核心结论

- 后端高德 `AMapClient.Search` 早已能返回最多 10 个候选（`/v3/place/text`），**缺的是暴露给前端的接口与前端交互**，不是高德能力缺失。
- 全链路新增一个能力需要同步改动 5 处：**proto 定义 → 重新生成 3 个 pb 文件 → trip-service service 层实现 → 网关接口+HTTP 路由 → 前端调用与 UI**。
- 网关 `returnData` 用 `protojson` 序列化回复，前端收到的字段是 **snake_case**（`poi_id`/`formatted_address`）；而网关入参解析时同时接受 camelCase 与 snake_case。前端建议统一写 `normalizeLocation` 兼容两种命名。
- 前端联想请求必须用 `silent: true`（该项目的 `request` 默认对非 0 code 弹 toast，输入过程会疯狂弹窗）。

## 关键原理

### 1. proto 扩展 RPC 的三件套生成

新增 RPC 后要重新生成 3 个文件：

```
trip.pb.go        # 消息定义（protoc-gen-go）
trip_grpc.pb.go   # gRPC 服务（protoc-gen-go-grpc）
trip_http.pb.go   # HTTP 路由与 handler（protoc-gen-go-http, kratos 专用）
```

本仓库 protoc 命令（从仓库根目录）：

```powershell
$env:Path = "D:\GoDev\Workspace\bin;" + $env:Path
protoc -I "services\trip-service\api" -I "third_party" `
  --go_out=paths=source_relative:"D:\Temp\opencode\tripproto" `
  --go-grpc_out=paths=source_relative:"D:\Temp\opencode\tripproto" `
  --go-http_out=paths=source_relative:"D:\Temp\opencode\tripproto" `
  "services/trip-service/api/trip/v1/trip.proto"
```

注意：`-I third_party` 提供 `google/api/annotations.proto`；`--go-http_out` 是 kratos 专属插件 `protoc-gen-go-http`。生成到临时目录后 diff 检查再拷回，避免直接覆盖出问题。**proto 路径若含中文，先在仓库根用相对路径跑，避免 PowerShell 把含中文的绝对路径传坏**。

### 2. 服务端实现的防漏点

service 层新增方法后，若 `TripService` 嵌入了 `UnimplementedTripServiceServer`，忘记实现也不报错，直到运行才返回 `Unimplemented`。**实现后必须 `go build ./...` 或查 gRPC 注册的接口断言**。

### 3. 网关三层：HTTP 路由 → service → biz 断言

- `server/http.go`：注册 `POST /carpool/trips/locations/suggest`，`requirePermission(..., "trip:publish")` 权限校验，`ctx.Bind(req)` → `tripSvc.SuggestLocations`。
- `service/trip.go`：薄转发到 `uc.SuggestLocations`。
- `biz/trip.go`：用类型断言探测客户端能力，缺失时返回「XX服务未配置」——这是本项目网关的既定模式（见《网关类型断言…》文档）。
- `data/trip_client.go`：`TripClient` 接口、`TripHTTPClient`（POST JSON）、`TripGRPCClient` 都要加方法。
- **测试桩 `mobile_compat_test.go` 的 `fakeTripClient` 必须同步补方法**，否则 `go test` 因接口不完整编译失败。

### 4. 前端交互设计

- 输入用 `watch(form.origin/destination)` + 300ms 防抖调 `suggestLocations({keyword, limit:8})`，用自增序号丢弃过期响应。**不要用 `u-input` 的 `@input`**：uview-plus 的 u-input 输入事件多平台不可靠，`watch` 一定触发。watch 里用「`originLocation.name === 当前文本`」判断：选中回填时文本与已选地点名一致则**不清空** location（否则点选后坐标被 watch 清掉，发布校验必失败）。
- `@focus` 重查、`@blur` 延迟 **200ms** 隐藏下拉（让点击项先于隐藏触发）；下拉容器加 `@mousedown.stop @touchstart.stop` 阻止冒泡导致 input 失焦提前隐藏，**不要用 `@mousedown.prevent`**（uni-app H5 兼容性差，会导致选项点不中）。
- 选中候选后回填 `name`（显示文本）与完整 location 对象（含 poiId/经纬度），后续 `previewTripPrice`/`publishTrip` 直接用该对象。
- 校验提交：`originLocation && destinationLocation` 必须存在（否则提示「请从联想列表中选择有效地点」），避免 text 与坐标不一致。
- 地图预览用 **高德静态地图**（`/v3/staticmap`）而非原生 `<map>` 组件：H5 端原生 `<map>` 需要 `h5.sdkConfigs.maps` 的 key 且渲染为空白（本项目只配了顶层 `aMapKey`），静态地图是一张 PNG 图片，H5/App 都能用 `<image>` 加载。

### 5. 高德静态地图 markers 参数（曾踩坑）

静态地图 `markers` 的正确格式（**样式冒号点列表**，多组用 `|` 分隔，同组多点用 `;` 分隔）：

```
markers=size,color,label:lng,lat;lng,lat|size,color,label:lng,lat
```

- 样式为 `size(可选 small/mid/large),color(0xXXXXXX),label(A-Z/0-9/单个汉字)`，样式与坐标之间是**冒号**，不是逗号。
- **错误写法**：`markers=mid,0xFF0000,116.37,39.92`（坐标紧跟逗号、无冒号）→ 高德返回 `{"status":"0","info":"UNKNOWN_ERROR","infocode":"20003"}`。
- 官方示例：`markers=mid,0xFF0000,A:116.37359,39.92437;116.47359,39.92437`。
- URL-encode（`|`→`%7C`、`,`→`%2C`、`:`→`%3A`、`;`→`%3B`）同样被接受，前端用 `URLSearchParams` 构造无碍。
- 有覆盖物时 `location`/`zoom` 可省略（系统自动以覆盖物几何中心为地图中心并计算缩放），但显式传更可控。

### 6. 静态地图 key 不落前端：网关代理

Web 服务 key 不应暴露给浏览器。方案是**网关代理**：key 留在服务端，前端 `<image>` 加载的是网关 URL。

- `pkg/amapx`：新增 `StaticMap(ctx, StaticMapRequest) (*StaticMap, error)`，内部 `buildURL("/v3/staticmap", params)` 注入 key；非 image Content-Type 时解析 `status/info` 转为 Go error。
- 网关 `server/map_routes.go`：注册 `GET /api/v1/maps/static?origin=lng,lat&destination=lng,lat&size=750*400&scale=2`，解析坐标后构造两个 `StaticMarker`（起点绿「起」/终点红「终」），`ctx.Response().Write(image.Data)` 直接回图片字节 + `Content-Type`。
- `auth_filter.go` 的 `isPublicPath` 要加 `/api/v1/maps/static`：`<image>` 加载图片无法带 `Authorization` 头，若走鉴权会被 401 拦截。
- 前端 `staticMapUrl` computed：`BASE_URL/api/v1/maps/static?origin=...&destination=...`，配合 `@error` 事件显示「地图加载失败」兜底文案。
- 网关测试：`fakeAmapRouteClient` 补 `StaticMap` 方法；断言响应 Content-Type 为 image/png、请求体含 2 个 marker。

## 示例（端到端验证脚本）

```powershell
# 1. 登录拿 token（验证码写入 redis）
docker exec 6974f781819a redis-cli SET "sms:code:driver:19912121212" "123456" EX 300
# POST /carpool/auth/login {"principal":"19912121212","role":"driver","code":"123456"} → access_token

# 2. 联想
# POST /carpool/trips/locations/suggest {"keyword":"北京南站","limit":5}
# → {"code":0,"data":{"locations":[{poi_id,name,formatted_address,longitude,latitude},...]}}

# 3. 发布（request_id 必填，driver_id 由网关注入）
# POST /carpool/trips {request_id,origin,destination,depart_time,seats_total}
# → {"code":0,"data":{"trip_id":...,"status":10}}

# 4. 清理软删
# DELETE /carpool/trips/{id}
```

## 常见误区 / 注意事项

- **protojson 输出 snake_case**：前端别只按 camelCase 取字段，写兼容解析（`item.poi_id ?? item.poiId`）。
- PowerShell 5.1 写中文 JSON 必须无 BOM（用 `[System.IO.File]::WriteAllText(path, s, New-Object System.Text.UTF8Encoding($false))`），否则 protojson 报 `syntax error (line 1:1)`；`curl -d "..."` 内联带引号也有编码风险，**中文/引号多的 body 优先用文件 `--data-binary @file`**。
- `request` 默认弹 toast，联想接口必须 `silent: true`。
- 改了 proto 后忘记重生成，或只重生成 pb.go 忘了 http/grpc，运行时会出现路由/方法缺失。
- `@blur` 里直接清空下拉会导致 `@click` 选不中，务必 setTimeout 延迟。
- `PublishTripRequest` 的 `request_id` **必填**：biz 层幂等逻辑在 `request_id` 为空时直接返回 `ErrInvalidTrip`（前端 `publishTripPayload` 已自动生成 `trip-${Date.now()}-...`，curl 手测必须带）。
- `trip:status` 状态码 10=已发布、0=草稿（发布接口返回 `status:10` 正常）。
- 静态地图 markers 冒号/分号格式写错会得到 `20003 UNKNOWN_ERROR`，与 key 无关，先查参数格式。

## 延伸方向

- 服务端加 city 参数按城市限定搜索，减少跨城市误匹配。
- 联想结果去重/合并（同一地点多进站口），按 score 排序。
- 静态地图加 polyline 展示行车路线（`paths` 参数，数据源可复用 `PreviewTripPrice` 的路线），或升级 H5 `h5.sdkConfigs.maps` 用原生交互地图。
