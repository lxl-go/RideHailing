## 一、顺风车乘客端模块

### 1. 功能页面布局

页面采用底部Tab导航结构，共5个Tab页：首页、行程、订单、消息、我的。

**首页**：顶部定位栏（显示当前城市 + 定位精度提示），中部为出行方式快捷入口卡片（顺风车/打车/班车），底部为推荐行程信息流（附近热门路线、即将出发的顺风车行程）。页面顶部天气状况展示组件（阴/晴/雨，点击可查看天气详情）。

**行程发布页**（从首页点击「发布行程」进入）：页面从上到下依次为：①路线选择区（起点输入框 + 终点输入框，支持地图选点和历史地址快速选择）②时间选择区（即时出发/预约出发，预约出发展示日历时间选择器）③行程设置区（座位数选择器 ±、是否可携带宠物开关、是否可吸烟开关、备注输入框）④底部固定按钮区（「发布行程」主按钮 + 「设置常用路线」副链接）。

**行程搜索页**（从首页点击「找行程」进入）：顶部筛选条件栏（出发地/目的地/出发时间/人数），结果列表为卡片式布局（每张卡片展示：车主头像+昵称+评分、车型+车牌、出发时间、起点-终点、剩余座位、预估价格），支持按时间/价格/评分排序。点击卡片进入行程详情页，详情页展示完整路线、车主信息、车辆照片、历史评价列表，底部「立即预约」按钮。

**我的页面**：顶部用户头像+昵称+实名认证状态，下方功能列表（我的行程/我的评价/紧急联系人/保险保障/设置）。「紧急联系人」页面可添加/编辑紧急联系人姓名+电话，「设置」页面包含实名认证入口、隐私设置、消息通知开关、关于我们。

### 3. 操作流程

#### 正常操作流程

**发布行程流程**：用户进入首页 → 点击「发布行程」→ 默认显示当前位置作为起点（可手动修改）→ 输入终点（支持地图选点和历史地址）→ 选择出发时间（即时出发默认当前时间+15分钟）→ 设置需求（座位数/备注）→ 点击「发布行程」→ 系统校验行程信息 → 发布成功 → 跳转至行程详情页 → 等待车主接单 → 有车主接单时推送通知。

**搜索预约流程**：用户进入首页 → 点击「找行程」→ 输入起点终点（或选择常用路线）→ 选择出发时间 → 查看结果列表 → 点击感兴趣的行程序卡 → 查看行程详情（车主信息/路线/评价）→ 点击「立即预约」→ 确认弹窗（显示预估价格/座位数）→ 确认预约 → 系统推送通知给车主 → 车主确认后订单状态变更为「待出发」。

**评价司机流程**：订单完成后 → 系统自动跳转至评价页（或从订单中心进入）→ 展示司机头像+姓名+车牌 → 点击星级（1-5星）→ 选择评价标签（多选：准时/车况好/态度好/驾驶平稳/路线熟悉）→ 可选输入文字评价 → 点击「提交评价」→ 评价成功 → 获得积分/优惠券奖励提示 → 返回订单列表。

**紧急求助流程**：行程中 → 点击页面底部「紧急求助」按钮（红色图标，常驻显示）→ 弹出两个选项「联系客服」「拨打110」→ 选择「联系客服」→ 一键拨打客服热线，同时系统发送位置+行程信息至客服后台 → 选择「拨打110」→ 确认弹窗「是否拨打110并同步位置给紧急联系人？」→ 确认后拨号+发送位置短信给紧急联系人。

#### 异常操作流程

- 定位失败：页面顶部提示「定位失败，请手动输入地址」+ 定位图标变灰 → 用户手动输入起点/终点 → 系统通过地名/关键字搜索匹配
- 验证码发送频繁：60秒内重复点击获取验证码 → 按钮置灰倒计时「60s后重新获取」→ 每日上限5次 → 超限提示「已超过每日发送次数，请明天再试」
- 实名认证审核中：用户查看认证状态显示「审核中，预计24小时内完成」→ 审核通过推送通知 → 审核驳回时提示原因+重新上传入口
- 发布行程被拦截：行程起点/终点相同 → 提示「起点和终点不能相同」→ 无法发布
- 车主取消订单：已确认的行程被车主取消 → 推送通知「车主取消了行程」+ 原因（可选）→ 返回行程搜索页 → 推荐其他可用行程
- 紧急求助误触：点击后弹窗可通过「取消」关掉 → 实际拨出后可在通话界面挂断 → 挂断后系统发送确认短信「您已挂断求助电话，如需帮助请再次联系」
- 评价提交失败：网络原因提交失败 → 本地保存草稿 → 下次进入评价页时提示「上次评价未提交成功，是否继续提交？」

### 4. 业务流程

**完整发单-接单-出行-评价链路**：

```
乘客发布行程 → 行程写入服务端 → 行程进入匹配池
    ↓
（车主端）车主搜索行程 → 车主确认接单 → 推送通知给乘客
    ↓
乘客收到「车主已接单」通知 → 订单状态「待出发」
    ↓
出发时间到达 → 乘客上车 → 车主确认出发 → 订单状态「行程中」
    ↓
行程结束 → 车主确认到达 → 订单状态「已完成」
    ↓
（可选）乘客评价司机 → 评价数据入库 → 更新司机评分
```

**数据流转**：乘客端操作 → Kratos passenger-service API → MySQL订单表/用户表更新 → 消息队列推送至管理端（订单状态同步）→ 管理端审核认证数据。WebSocket实时推送订单状态变更至乘客端。

### 5. 业务约束规则

| 规则类别 | 规则内容 |
|---------|---------|
| 业务规则 | 同一用户同一时间仅可有1个进行中的行程；实名认证是发布行程的前置条件；乘客取消行程每日上限3次 |
| 时效规则 | 车主确认接单超时30分钟自动取消；实名认证审核48小时内完成；验证码有效期5分钟 |
| 合规要求 | 乘客手机号在行程详情页对车主脱敏展示（仅显示后4位）；紧急联系人信息加密存储；保险覆盖说明需在行程开始前展示并确认 |
| 操作红线 | 同一设备每日验证码发送上限5次；评价提交后不可修改；紧急联系人最多设置3人 |
| 异常处理 | 车主取消订单后系统自动推荐替代行程；定位失败降级为手动输入；网络异常时关键操作本地缓存待重试 |

### 6. 权限范围

| 用户状态 | 可操作范围 |
|---------|-----------|
| 游客（未登录） | 首页查看、行程搜索查看（不可预约）、城市切换、定位 |
| 已登录未实名 | 发布行程（不可，提示先实名）、行程搜索+预约（不可，提示先实名）、评价查看（不可）、个人信息查看编辑 |
| 已实名认证 | 全部功能：发布行程、预约行程、乘车、评价、紧急求助、保险查看、行程分享 |

## 二、班车乘客端模块（工单 02 补强）

### 1. 功能页面布局

班车入口位于首页「出行方式快捷入口卡片」中的「班车」图标，点击后进入班车专用页面。

**班车首页**：顶部城市选择 + 搜索框（搜索班线名称/站点名称），下方为推荐班线列表（卡片展示：线路名称、起点→终点、首班/末班时间、票价区间、剩余座位）。列表支持按距离/价格/时间排序。

**班线详情页**（点击班线卡片进入）：①顶部班线信息区（线路名称、总里程、预计时长）②站点时序列表（按 offset_min 升序展示所有站点：站点名称/到达时间/上车点/下车点标识，上车站与下车站不可选择同一站点）③班次日历视图（按月展示可预约日期，有班次的日期高亮显示剩余座位数）④费用说明区（票价、优惠券可用标记）⑤底部「选择班次」按钮。

**购票页**（选择班次后进入）：①顶部行程概要（线路名称、日期、所选班次时间）②站点选择区：上车站下拉列表（可选站点标记「可上车」）→ 下车站下拉列表（可选站点标记「可下车」，自动过滤已选上车站）→ 选中后展示该段票价③座位选择器（剩余座位数展示 + 选择人数 ±）④优惠券选择（可用券列表 + 不可用券原因灰色展示）⑤费用汇总（票价×人数 - 优惠券抵扣 = 实付）⑥底部「确认购票」按钮。

**班车订单页**：顶部Tab「全部/待出行/已完成/已取消」，列表卡片展示班线名称、日期、班次时间、上车站→下车站、座位数、支付金额、状态标签。待出行订单展示乘车二维码+验票须知；已完成订单展示评价入口。

| 02-P04 | 上下车站选择 | 上车站与下车站不可选择同一站点，自动过滤冲突选项 |
| 02-P05 | 班次日历 | 按月日历展示可预约日期，标记剩余座位 |

### 3. 操作流程

**购票流程**：首页点击「班车」→ 浏览/搜索班线 → 点击班线卡片 → 查看站点时序和班次日历 → 选择出行日期 → 选择一个班次 → 进入购票页 → 选择上车站（下拉列表仅展示「可上车」站点）→ 选择下车站（自动过滤已选上车站）→ 查看段票价 → 选择座位数 → 选择优惠券（可选）→ 确认费用 → 点击「确认购票」→ 支付 → 购票成功 → 展示乘车二维码。

**乘车流程**：发车当日 → 乘客在班车订单列表找到待出行订单 → 点击展示乘车二维码 → 到达上车站 → 司机/验票员扫码 → 验票成功 → 乘客上车 → 司机确认发车 → 行程完成。

### 4. 业务约束规则

| 规则类别 | 规则内容 |
|---------|---------|
| 业务规则 | 上车站与下车站不可为同一站点；购票后站点信息快照锁定，管理端修改站点不影响已有订单 |
| 时效规则 | 发车前30分钟停止购票；发车前2小时内不可退票；发车后未验票自动取消并扣费 |
| 合规要求 | 乘车二维码每30秒动态刷新；订单数据保留≥3年 |
| 操作红线 | 同一乘客同一班次不可重复购票；优惠券核销后不可撤销 |
| 异常处理 | 班次取消（管理端操作）：自动通知乘客 + 全额退款 + 补偿券发放；验票失败：展示失败原因 + 人工核验入口 |

### 5. 权限范围

| 用户状态 | 可操作范围 |
|---------|-----------|
| 游客 | 班线搜索/查看班线列表和站点时序（不可购票） |
| 已登录未实名 | 查看班线详情和班次日历（不可购票） |
| 已实名认证 | 全部功能：购票/乘车/退票/评价 |

## 三、AI智能出行助手模块

### 1. 功能页面布局

AI助手入口为首页底部悬浮按钮（圆形，渐变蓝色，中间为AI图标），点击后全屏进入对话式交互界面。页面布局从上到下：①顶部导航栏（「AI出行助手」标题 + 关闭按钮）②对话消息流区域（气泡式消息，助手消息靠左灰色气泡，用户消息靠右蓝色气泡；时间戳+天气动态卡片穿插展示）③底部输入区（语音输入按钮 + 文本输入框 + 发送按钮）。输入框上方为快捷指令卡片（横向滚动：一键叫车/查天气/避雨路线/常用地址）。

天气预警场景下，首页顶部出现横幅通知（黄色/橙色/红色预警色条），文案如「暴雨黄色预警：预计等待时间+8分钟，费用+15%」，点击横幅进入AI助手界面并自动触发天气咨询对话。

智能体交互主界面（进入雨天场景后）：对话区插入降雨图层卡片（展示当前降雨强度地图缩略）和拥堵热力图卡片，下方自动展示「推荐方案」卡片组：车型推荐卡（如「推荐SUV，雨天路况更安全」）、智能出发时间卡（如「建议推迟30分钟出发，避开强降雨时段」）、费用预测卡（如「预估费用¥45-¥68」）。底部输入框上方自动出现快捷按钮：「规划避雨路线」「查看积水路段」「叫车」。

| 编号 | 功能 | 说明 |
|------|------|------|
| 10-P01 | 天气预警推送 | 黄色/橙色/红色预警自动推送通知（系统消息+首页横幅），展示等待时间变化和费用浮动 |
| 10-P02 | AI对话界面 | 全屏对话式交互，支持文本输入和语音输入，消息气泡展示 |

| 10-P05 | 智能出发时间 | 根据天气预测+路况分析推荐最佳出发时间 |

| 10-P11 | 异常天气应对 | 红色预警场景：司机驾龄>5年、强制四驱车辆、紧急联系人自动通知、无条件免费取消 |
| 10-P12 | 道路积水上报 | 拍照上传→AI识别积水深度→更新订单/上报市政/发放补偿券 |
| 10-P13 | 语音输入 | 支持语音转文字输入对话内容，集成语音识别 |

### 3. 操作流程

#### 正常操作流程

**雨天智能叫车流程**：系统收到天气预警（黄色及以上）→ 首页弹出横幅通知 + 系统通知推送 → 用户点击横幅 → 进入AI助手界面 → AI主动发送消息「当前XX区发布暴雨黄色预警，预计等待时间增加8分钟，费用上浮15%。有什么可以帮您？」→ 用户输入「帮我叫车去公司」→ AI处理请求 → 展示推荐方案卡（车型推荐/出发时间建议/费用预估）→ 用户点击「确认叫车」或修改条件后确认 → 系统调起顺风车/打车下单流程 → 自动填入避雨路线 → 下单成功 → 返回订单跟踪页。

**避雨路线咨询流程**：用户主动打开AI助手 → 输入「我要去XX，避开积水路段」→ AI调用 `calculate_rain_route` 函数（参数：起点终点、避让标记[积水路段,隧道]、偏好[最安全]）→ 返回路线方案 → 气泡展示路线信息（距离/时长/风险等级/备选路线）→ 地图卡片展示两条路线对比（主路线绿色/备选路线蓝色，积水段红色标记）→ 用户点击「使用此路线」→ 自动填充到发单页。

**积水上报流程**：行程中遇到积水路段 → 用户点击AI助手中的「上报积水」→ 调起相机 → 拍摄积水照片 → AI识别积水深度（超过轮胎1/2/淹没排气管等）→ 展示识别结果 → 用户确认后上传 → 系统更新订单路线避开该路段 → 同时上报市政部门 → 用户获得补偿券（如¥5无门槛券）。

#### 异常操作流程

- 天气数据获取失败：网络原因无法获取天气数据 → AI提示「暂时无法获取实时天气信息，建议您手动输入出发信息」→ 降级为普通对话模式
- 路线计算超时：调用 `calculate_rain_route` 超过5秒未返回 → 提示「路线计算较慢，请稍候」→ 超10秒后返回兜底路线（仅避开已知积水点）
- 语音识别失败：语音输入无法识别 → 提示「未听清，请再说一遍」或建议切换文字输入
- Coze对话服务不可用：AI服务端异常 → 降级为固定问答模板 → 提示「智能助手暂时休息，已为您切换基础服务模式」
- 红色预警强制措施触发：红色预警下用户叫车 → 系统自动限制仅匹配驾龄>5年+四驱车辆 → 如无可用车辆 → 提示「当前红色预警，暂无符合条件的车辆，建议您推迟出行或联系紧急联系人」

**取消订单流程**：用户在待出发订单卡片点击「取消订单」→ 弹窗选择取消原因（至少选择1项，支持填写其他原因）→ 点击「确认取消」→ 系统校验订单是否可取消（距出发时间>30分钟可免费取消）→ 校验通过 → 订单状态变更为「已取消」→ 页面跳转回订单列表 → 推送通知给车主。如需扣款则展示扣款金额+剩余退款。

## 五、模块之间的链路闭环

### 4.1 数据流转总览

三个乘客端模块通过统一的数据中台形成面向用户的完整出行体验：

**顺风车乘客端**是用户流量的起点和终点——用户从注册认证开始，通过发布行程/搜索行程进入出行流程，行程完成后通过评价系统结束体验闭环。产生的用户数据和行程数据被订单中心消费和管理端消费。

**AI智能出行助手**是智能化交互入口——它在天气异常场景下主动触达用户，引导用户完成叫车操作（调用顺风车或订单中心的创建接口），同时通过 Coze 对话和路线计算为订单提供智能决策支持。积水上报数据反馈至管理端市政对接模块。

**订单中心**是状态流转的中枢——它消费顺风车模块创建的订单和AI助手触发的订单，通过WebSocket实时同步状态变更给乘客端展示，支持取消、跟踪、评价等全生命周期操作。费用数据透传至管理端财务报表。

### 4.2 端到端用户旅程闭环

以「用户在外出时突遇暴雨→AI助手主动提醒→智能叫车→实时跟踪→到达评价」的完整场景为例：

```
[用户场景] 用户在商场购物结束，外面突降暴雨
    ↓
[天气预警] 气象系统发布暴雨黄色预警 → Kratos passenger-service 接收
    ↓
[AI助手] 乘客端首页弹出横幅「暴雨预警」
    ↓
用户点击横幅 → 进入AI助手对话界面
    ↓
[AI助手] AI主动问候：「当前XX区暴雨黄色预警，等待+8分钟，费用+15%」
    ↓
用户输入：「回家，XX小区」
    ↓
[AI助手] AI调用 calculate_rain_route(起点=商场, 终点=XX小区, 避让=积水路段)
    ↓
[AI助手] 返回路线方案 + 推荐SUV车型 + 建议15分钟后出发
    ↓
用户点击「确认叫车」
    ↓
[订单中心] 创建订单（带避雨路线参数）→ 状态「待接单」
    ↓
[派单引擎] 匹配到符合条件的司机（SUV+驾龄3年+车内备伞）
    ↓
[订单中心] 状态变更为「已接单」→ 推送通知 + WebSocket连接建立
    ↓
[订单中心] 司机到达 → 状态「已到达」→ 用户收到推送
```

### 4.5 数据一致性保障

- **订单状态一致性**：乘客端所有订单状态以服务端为准，前端状态仅作展示；客户端因断网等原因状态延迟时，页面提供手动刷新和自动状态校正
- **实时位置一致性**：司机位置通过WebSocket持续推送，服务端保留最近30秒的位置快照，客户端断线重连后补发离线期间的位置数据
- **评价一致性**：评价提交后不可修改，如网络原因提交失败，本地缓存评价草稿，下次进入自动提示续传
- **天气数据一致性**：天气预警以服务端推送为准，乘客端定时拉取兜底（15分钟间隔），服务端气象数据每15分钟从气象API同步
- **取消操作一致性**：取消订单请求使用幂等键防止重复处理，取消后订单不可恢复

### 6.4 工单02 — 班车购票页完整原型补强

**入口与页面结构**：乘客从首页「班车」入口进入班车购票页。页面采用“日历筛选 + 班次卡片 + 站点选择 + 确认购票”四段式布局：

1. 顶部为发车日历条，横向展示未来7天，默认选中今天；点击“更多日期”打开月历弹层，月历中用绿色圆点标记有班次日期，用灰色禁用无班次日期。
2. 日历下方为班线筛选区，包含起点城市/终点城市、上车站、下车站、发车时段、余票状态四个筛选项。
3. 中部为班次卡片列表，每张卡片展示班线名称、发车时间、预计到达时间、车辆类型、票价、剩余票数、站点数量、准点率标签。
4. 点击班次卡片进入站点选择面板，左侧为上车站时序列表，右侧为下车站时序列表，底部固定显示票价、余票、已选站点和「确认购票」按钮。

**站点时序展示**：站点按 `offset_min` 升序排列，首站固定显示“首站 0分钟”。每个站点行展示站点名称、预计到达时间、距首站偏移、可上车/可下车标签。示例：A站 0分钟 → B站 20分钟 → D站 30分钟 → C站 40分钟。

**余票展示规则**：班次卡片展示“剩余 N 张”；N≤5 时红色提示“余票紧张”；N=0 时卡片置灰，按钮变为“已售罄”，不可进入购票确认。站点选择后按区间库存重新计算余票，若该区间无票，底部按钮置灰并提示“该上下车区间暂无余票”。

**排重交互规则**：同一站点不可同时作为上车站和下车站。用户选择上车站后，下车站列表中同一站点置灰并提示“上车站不可作为下车站”；用户选择下车站后，上车站列表中同一站点同样置灰。下车站时间必须晚于上车站，早于或等于上车站的站点置灰。

**确认购票弹窗**：弹窗展示班线、发车日期、上车站、下车站、预计上车时间、预计到达时间、票价、优惠券抵扣、实付金额、退票规则摘要。用户确认后创建班车订单，订单来源标记为“班车”，并保存站点快照，避免后续站点配置变更影响历史订单。

### 8.5 非功能验收修订

1. 乘客端网关统一透传 `X-Request-Id`、`traceparent`、`x-user-id`，页面报障时必须记录请求时间、接口路径和响应码。
2. 下单、取消、评价属于登录态操作；未登录返回 401，越权访问本人以外订单返回业务失败或 403。
3. 下单创建订单必须保持事务一致：订单创建与余座扣减要么同时成功，要么同时回滚。
4. 座位扣减需具备并发保护；当余座不足时，页面提示“余座不足，请重新选择行程”。
5. `workorder02/03/04/07/10/11` 在真实接口接入前保留 mock 作为原型验收依据，但最终验收不得以 mock 数据替代服务联调结果。
