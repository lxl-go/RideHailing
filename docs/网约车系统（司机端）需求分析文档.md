## 一、顺风车司机端模块

### 1. 功能页面布局

页面采用底部Tab导航结构，共4个Tab页：听单、行程、消息、我的。

**听单页**（默认首页）：顶部为状态切换栏——「听单中/暂停听单」滑块开关，绿色=在线听单、灰色=暂停。状态栏下方为听单区域：卡片式展示附近可接的顺风车行程请求（每张卡片包含：乘客起点~终点、出发时间、距离司机当前位置、预估收入）。听单中时卡片列表自动刷新，有行程请求时播放提示音+震动。底部区域展示当日接单统计：今日订单数/今日收入/在线时长。

**行程页**：顶部Tab切换「进行中/已完成/已取消」，列表为订单卡片（订单编号、乘客起点~终点、出发时间、乘客头像+昵称、订单金额、状态标签）。进行中订单卡片底部操作按钮：到达起点/确认出发/确认到达（按当前状态动态展示）。已完成订单卡片底部：查看详情/再次评价。

**我的页面**：顶部司机头像+昵称+服务评分星星展示。功能列表区：①实名认证入口（未认证时红色提示「去认证」）②车辆管理（车辆信息查看/编辑、年检提醒、保险提醒）③收入统计（日/周/月收入趋势）④行程记录（历史行程列表）⑤紧急联系人设置 ⑥设置（消息通知开关/隐私设置/退出登录）。车辆管理页面内嵌车辆图片、品牌型号、车牌号、年检到期日（距到期30天黄色预警、7天红色预警）、保险到期日。

**消息页面**：消息列表，分类签：系统通知、订单消息、平台公告。系统通知包含审核结果、车辆年检提醒、保险到期提醒；订单消息包含接单提醒、乘客取消通知、改派通知；平台公告包含规则更新、活动通知。

### 3. 操作流程

#### 正常操作流程

**实名认证流程**：司机注册登录后进入「我的」→ 点击实名认证入口（红色提示）→ 进入认证页 → 拍摄或上传身份证正面照 → 系统OCR自动识别填入姓名/身份证号 → 手动核对修正 → 上传身份证反面照 → 上传驾驶证正本照 → 自动识别准驾车型/有效期 → 填写有效期（系统自动填充后可手动修正）→ 点击「提交审核」→ 页面展示「审核中，预计24小时内完成」→ 审核通过后推送通知 + 我的页面认证状态更新为绿色「已认证」。

**接单流程**：司机进入「听单」页 → 打开「听单中」开关（默认关闭，首次需开启位置权限）→ 系统开始实时推送附近订单 → 订单以卡片形式弹出（含起点终点/距离/预估收入/乘客评分）→ 同时播放提示音（可设置震动）→ 司机在15秒内点击「接单」或滑动接单 → 超过15秒未操作则订单自动消失 → 接单成功后页面跳转至该订单详情 → 显示乘客信息+起点导航按钮。

**年检保险提醒处理**：系统推送年检提醒通知 → 司机点击进入车辆管理 → 查看年检到期日 → 如已完成年检点击「已年检」→ 上传新行驶证照片 → 系统OCR识别新有效期 → 审核通过后更新年检状态 → 保险提醒流程同上。

**今日班车排班查看流程**（工单02补强）：司机进入「我的」→ 点击「今日班车排班」→ 页面顶部展示今日日期+班次数 → 下方按时间顺序展示班线卡片（班线名称/线路起终点/发车时间/车辆信息/车牌号）→ 点击卡片展开站点时序列表（站点名称/到达时间/上车人数/验票状态）→ 发车前30分钟自动推送提醒 → 发车时点击「确认发车」→ 系统更新排班状态 → 乘客端收到上车提醒。

**收入明细查看流程**（工单03补强）：司机进入「我的」→ 点击「收入统计」→ 默认展示日/周/月汇总趋势图 → 点击「查看明细」→ 按时间倒序展示每笔订单收入条目：订单编号/乘客起点终点/订单金额/平台抽成(-XX元)/奖励补发(+XX元)/退款扣减(-XX元)/实收金额 → 每笔可点击展开计算明细 → 底部展示汇总（总订单金额/总抽成/总奖励/总退款扣减/净收入）。

#### 异常操作流程

- 实名认证驳回：审核驳回 → 推送通知 + 我的页面显示驳回原因（如「驾驶证照片模糊」）→ 司机点击重新提交 → 查看驳回详情 → 重新拍摄上传 → 再次提交审核
- 年检/保险逾期：逾期未处理 → 系统自动暂停听单权限 → 我的页面红色提示「年检已逾期，请及时更新」→ 完成更新审核通过后自动恢复听单权限
- 接单超时：司机正在操作其他页面未注意到派单 → 15秒倒计时结束后订单自动消失 → 页面提示「有订单被自动放弃，请保持听单页可见」→ 单日累计放弃超5次 → 当日暂停听单权限
- 乘客取消已接订单：司机已接单后被乘客取消 → 推送通知「乘客已取消订单」+ 原因 → 订单从进行中移至已取消列表 → 司机可查看乘客取消原因
- 车辆信息变更未更新：司机更换车辆但未更新信息 → 乘客上车发现车型/车牌不符 → 投诉 → 管理端审核后暂停司机接单权限 → 需重新提交车辆信息

### 4. 业务流程

**司机完整作业链路**：

```
司机注册 → 实名认证（身份证+驾驶证）→ 提交审核 → 管理端审核通过
    ↓
绑定车辆信息 → 提交审核 → 审核通过 → 司机可开始接单
    ↓
打开听单 → 系统推送附近订单（GEO距离排序）
    ↓
接单/抢单（15秒决策窗口）
    ↓
接单成功 → 获取乘客信息+起点导航
    ↓
司机到达起点 → 点击「已到达」→ 乘客端收到通知
    ↓
乘客上车 → 司机确认出发 → 订单状态「行程中」→ 实时位置上报
    ↓
到达目的地 → 司机确认到达 → 订单完成
    ↓
（可选）评价乘客 → 评价入库
```

**认证数据流转**：司机提交认证信息 → Kratos driver-service → 写入审核表 → 管理端审核 → 审核结果回调 → 通知司机端。

**位置上报流程**：司机端每3秒上传GPS坐标 → Redis GEO更新当前位置 → 同时写入位置历史流 → 乘客端通过WebSocket读取司机位置 → 管理端轨迹查询通过Redis热存+MySQL冷存获取。

### 5. 业务约束规则

| 规则类别 | 规则内容 |
|---------|---------|
| 业务规则 | 司机必须完成实名认证+车辆绑定并通过审核方可接单；单日累计放弃接单≥5次暂停当日听单权限；年检/保险逾期自动暂停接单 |
| 时效规则 | 接单决策窗口15秒，超时自动放弃；到达起点后15分钟未确认出发订单自动取消；确认出发后位置上报间隔≤3秒 |
| 合规要求 | 身份证/驾驶证信息加密存储，脱敏展示（仅显示后4位）；司机端不可查看乘客真实手机号（通过平台中转通话） |
| 操作红线 | 不可在行程中关闭位置上报（自动强制开启）；不可代替乘客点击确认到达；确认到达后不可修改订单状态 |
| 异常处理 | 乘客取消订单：系统自动计算是否需扣款，扣款金额进入司机账户；车辆故障：司机可发起异常上报取消订单（不影响服务分） |
| 班车排班约束 | 同一司机同一日期排班不可重叠；发车前2小时禁止普通修改排班；管理端修改排班需推送司机端确认通知（工单02补强） |
| 收入计算约束 | 每笔收入 = 订单金额 - 平台抽成(实付×抽成率) + 奖励补发 - 退款扣减(乘客取消扣款不计入司机扣减)；收入明细与 transaction_ledger 逐笔可对账（工单03补强） |

### 6. 权限范围

| 司机状态 | 可操作范围 |
|---------|-----------|
| 未认证（注册未提交认证） | 基本信息编辑、我的页面查看（不可接单、不可听单） |
| 认证审核中 | 查看审核状态、基本信息编辑（不可接单、不可听单） |
| 已认证 在岗（听单中） | 全部功能：接收派单、接单、行程管理、评价、紧急求助、位置上报 |
| 已认证 离岗（暂停听单） | 查看已完成/已取消订单、评价查看、收入统计、车辆管理、消息查看（不接收派单） |
| 已认证 暂停（逾期/处罚） | 查看受限：可查看处罚原因和申诉入口，不可接单不可听单 |

## 二、订单中心与派单（司机视角）模块

### 1. 功能页面布局

本模块与顺风车司机端的「行程」Tab深度整合，在听单页和行程页中嵌入派单与订单管理功能。

**听单页-派单区域**：司机打开听单后，页面底部出现半屏派单面板。面板顶部为派单播报区（文字+语音播报「新订单到！」），中部为订单卡片——展示：起点→终点、乘客上车点距司机距离（米/km）、预估收入、乘客评分（星级）、订单类型（即时/预约）。卡片底部为操作按钮组：「接单」（绿色大按钮 占60%宽度）+「跳过」（灰色小按钮 占40%宽度）。接单后卡片切换为「已接单确认」状态，展示乘客电话图标（点击后平台中转呼叫）+ 导航按钮（跳转第三方地图导航）。

**行程页-进行中订单**：顶部为当前进行中订单的状态推进条——「已接单→已到达→行程中→已到达」，当前步骤高亮显示。中间地图区域（展示乘客起点、路线、司机当前位置、乘客实时位置）。底部信息卡：乘客头像+昵称（脱敏）、上车点地址、下车点地址、预计里程、预估收入、距离乘客距离。底部操作按钮根据当前状态变化：状态「已接单」——「导航至起点」「联系乘客」「到达起点」；状态「行程中」——「导航至终点」「联系乘客」「确认到达」；状态「已到达」——「等待乘客上车」（等待超时10分钟可取消）。

**位置上报控制**：行程中页面顶部有定位状态图标（绿色=定位正常 灰色=定位异常）。司机端自动开启位置上报，无需手动操作。如定位权限被关闭，页面展示弹窗「开启位置权限以正常接单」，拒绝后无法开始行程。

**轨迹回放入口**：在已完成订单的详情页，底部有「查看轨迹回放」按钮。点击后进入全屏地图模式，展示历史行驶路线动画（从起点到终点），支持播放/暂停/拖动进度条，右上角显示总里程/总时长/平均速度。

### 3. 操作流程

#### 正常操作流程

**听单→接单→接驾→行程→完成全流程**：

①听单接单：司机进入听单页 → 确认听单中状态（绿色）→ 系统自动推送附近订单卡片 → 语音播报「新订单」→ 司机查看订单信息（起点/终点/距离/收入）→ 点击「接单」→ 接单成功 → 页面切换至订单详情 → 展示乘客上车点地图 → 点击「导航至起点」→ 唤起地图APP。

②到达接驾：司机到达乘客起点附近 → 点击「到达起点」→ 状态变更为「已到达」→ 乘客端收到通知 → 页面展示「等待乘客上车」→ 等待超时10分钟可点击「取消订单」（计入司机取消）。

③行程中：乘客上车 → 司机点击「确认出发」→ 状态变更为「行程中」→ 自动开始位置上报（每3秒）→ 页面顶部展示预计到达时间+剩余距离 → 司机可实时查看路线 → 到达目的地附近时系统震动提示。

④完成行程：到达目的地 → 司机点击「确认到达」→ 弹窗确认「是否已到达乘客目的地？」→ 确认后状态变更为「已完成」→ 展示本单收入+总里程+时长 → 跳转评价页。

**轨迹回放流程**：进入已完成订单详情 → 点击「查看轨迹回放」→ 进入全屏地图 → 自动从起点开始动画播放历史行驶轨迹 → 底部进度条显示时间轴 → 可拖动进度条跳转到任意时间点 → 播放速度可调（1x/2x/4x）→ 右上角展示汇总数据（总里程/时长/平均速度）。

#### 异常操作流程

- 定位权限被关闭：听单时检测到GPS权限关闭 → 弹窗提示「请开启位置权限以接收附近订单」→ 引导至系统设置 → 权限开启后自动恢复听单
- 连续跳过过多：连续跳过3个订单 → 系统提示「已跳过多个订单，暂停派单5分钟」→ 听单页显示倒计时「剩余4分32秒恢复派单」→ 5分钟后自动恢复
- 乘客未上车超时：司机到达起点后乘客10分钟未上车 → 页面提示「乘客未确认上车」→ 司机点击「取消订单」→ 选择取消原因（乘客未到/联系不上乘客）→ 取消后不计入司机责任订单
- 导航APP未安装：点击导航但手机未安装高德/百度/腾讯地图 → 提示「未检测到地图APP」→ 提供扫码下载入口或展示路线文字指引
- WebSocket断线：连接断开 → 顶部提示「网络连接异常，正在重连」→ 自动重连（最多5次，间隔递增）→ 重连成功后补发离线期间的位置数据 → 重连失败则提示「请检查网络连接」
- 位置上报失败：GPS信号弱（地下车库/隧道）→ 页面顶部定位图标变灰色 → 提示「GPS信号弱，位置更新可能延迟」→ 信号恢复后自动续传 → 超过30秒无位置则服务端标记「位置异常」

### 4. 业务流程

**派单引擎→司机端→乘客端→管理端完整链路**：

```
乘客下单 → 订单进入派单引擎
    ↓
派单引擎执行规则a/b/c/d → 多维评分排序
    ↓
选出最优司机 → 通过WebSocket推送至司机端
    ↓
司机端收到派单 → 语音播报+卡片展示 → 15秒倒计时
    ↓
司机接单 → 回调派单引擎 → 更新订单状态「已接单」
    ↓
推送至乘客端「司机已接单，正在赶来」
    ↓
推送至管理端 → 订单列表更新
    ↓
（同时）派单引擎锁定该司机 → 该司机不再接收新派单
    ↓
行程结束 → 司机确认到达 → 更新订单状态「已完成」
    ↓
推送至乘客端评价页 → 推送至管理端归档
    ↓
派单引擎释放司机 → 司机回到派单池 → 可接收新订单
```

**位置上报数据流**：

```
司机端GPS (每3秒) → Kratos driver-service
    ↓
写入 Redis GEO（热存，保留7天）
    ↓
写入 位置历史流（Kafka/Pulsar）
    ↓
消费者写入 MySQL（冷存，保留30天）→ 归档存储
    ↓
WebSocket推送 → 乘客端（实时位置渲染）
    ↓
HTTP查询 → 管理端（轨迹回放/历史轨迹）
```

**订单状态机**：

```
待接单 → 已接单 → 已到达 → 行程中 → 已完成
  ↓         ↓         ↓         ↓
  (超时取消) (乘客取消) (司机取消) (异常)
```

### 5. 业务约束规则

| 规则类别 | 规则内容 |
|---------|---------|
| 接单时效 | 派单推送后15秒内需响应，超时自动放弃；连续跳过3笔暂停派单5分钟；每日放弃+跳过≥10次暂停当日听单 |
| 服务分规则 | 乘客投诉核实扣分：迟到扣2分/态度差扣3分/绕路扣5分/取消扣1分（非责任取消不扣）；高分司机（≥4.8）优先派单 |
| 位置上报规则 | 行程中强制开启GPS（不可手动关闭）；上报间隔≤3秒；上报精度≥10米；超过30秒无位置标记「位置异常」计入考核 |
| 资质合规 | 未完成年检自动暂停接单；保险过期自动暂停接单；驾驶证到期前30天提醒，到期自动暂停 |
| 拒单/取消规则 | 接单后无故取消：首次警告+扣3分，第二次扣5分+暂停听单1天，第三次扣10分+暂停3天 |
| 异常上报处理 | 车辆故障/交通事故：司机可发起异常上报 → 自动取消当前订单（不计入责任）→ 暂停接单至异常解除 |
| 操作红线 | 不可在行程中关闭位置上报；不可代乘客点击确认到达；不可在非接单状态下接收乘客线下交易 |

### 6. 权限范围

| 司机状态 | 可操作范围 |
|---------|-----------|
| 未认证 | 不可接收任何订单、不可进入听单页 |
| 认证审核中 | 不可接收订单，可查看认证进度 |
| 已认证 在岗（接单中） | 全部派单功能：接收派单、接单/跳过、实时跟踪、位置上报、到达确认、轨迹回放 |
| 已认证 离岗（暂停听单） | 查看已完成订单、轨迹回放、收入统计（不可接新单） |
| 已认证 暂停（逾期） | 不可接单，可查看处罚/逾期原因和申诉入口 |

## 三、模块之间的链路闭环

### 3.1 司机端内部模块数据流转

**顺风车司机端模块**是司机身份和作业准入的基础——认证通过后方可进入订单中心与派单系统。两个模块的关系如下：

```
司机实名认证 + 车辆绑定（顺风车模块）
    ↓ 审核通过
司机进入订单中心（派单模块）
    ↓
听单中 → 接收派单 → 接单 → 行程 → 完成
    ↓
评价乘客（顺风车模块）
    ↓
服务分更新（影响后续派单优先级）
```

顺风车模块产生的认证状态、车辆信息、年检/保险状态是派单模块的前置约束条件；派单模块产生的接单记录、完单量、乘客评价反哺顺风车模块的司机评分和收入统计。

### 3.2 跨端全链路作业闭环

以「司机上线听单→接单→接驾→行程→完成→结算」的完整司机作业周期为例：

```
[司机端] 司机上线 → 打开听单开关
    ↓
[Kratos driver-service] 司机状态更新为「在线」→ 加入派单池
    ↓
[管理端] 管理端可查看在线司机列表、分布热力图
    ↓
[乘客端] 乘客下单 → 派单引擎执行规则a/b/c/d
    ↓
[派单引擎] 多维评分 → 选出最优司机 → 推送至[司机端]
    ↓
[司机端] 派单播报 → 司机接单
    ↓
[Kratos driver-service] 订单状态「已接单」
    ↓
  ┌──→ [乘客端] 推送「司机已接单」+ 司机信息+实时位置
  └──→ [管理端] 订单列表更新
    ↓
[司机端] 导航至起点 → 到达 → 点击「已到达」
    ↓
  └──→ [乘客端] 推送「司机已到达」+ 上车提醒
    ↓
[司机端] 乘客上车 → 司机点击「确认出发」
    ↓
[司机端] 开始位置上报（每3秒）→ Redis GEO更新
    ↓
  ┌──→ [乘客端] WebSocket接收司机位置 → 地图渲染
  └──→ [管理端] 轨迹数据入库 → 可实时查看
    ↓
[司机端] 到达目的地 → 点击「确认到达」
    ↓
[Kratos driver-service] 订单状态「已完成」→ 派单引擎释放司机
    ↓
  ┌──→ [乘客端] 跳转评价页 + 费用展示
  ├──→ [司机端] 跳转评价页（评价乘客）+ 订单收入展示
  └──→ [管理端] 订单归档 → 进入对账流程
    ↓
[财务管理] 凌晨对账 → 该笔订单收入进入司机账单
    ↓
[数据分析] 该笔订单进入统计宽表 → 司机服务分更新
```

### 3.5 数据一致性保障

- **派单一致性**：派单引擎使用Redis分布式锁确保同一订单不被重复派发；司机接单后订单状态锁定，派单引擎不再推送给其他司机；司机端接单成功以服务端回调为准，前端按钮状态不保证最终一致
- **位置一致性**：GPS坐标以服务端收到的时间戳为准；断线重连后补发离线期间的位置快照（每5秒一个采样点）；乘客端收到的位置以服务端转发的最终位置为准
- **状态一致性**：订单状态变更以服务端状态机为准，司机端仅发起变更请求；服务端处理成功后回推确认；如司机端因断网无法收到回调，从上一次成功回调的状态继续
- **收入一致性**：订单收入以订单完成时服务端计算的最终金额为准；预估收入仅作参考，实际收入以账单为准；司机端展示的收入数据来自服务端财务模块

## 四、AI 智能出行助手（司机端场景）

### 4.1 功能页面布局

AI 智能出行助手采用高德天气预警 + Coze API 实现的轻量级场景集成。司机端无独立 AI 助手入口，而是将 AI 能力以内聚组件形式嵌入现有场景：

| 嵌入位置 | AI 能力 | 触发方式 |
|---------|---------|---------|
| 听单页天气区域 | 恶劣天气预警展示 + 路线建议 | 自动（天气API数据刷新） |
| 行程中导航 | 积水路段上报与绕路建议 | 手动（点击「上报积水」按钮） |
| 接单决策 | 实时路线风险提示（暴雨/积水） | 自动（系统根据位置和天气数据计算） |
| 紧急求助 | 智能客服对话（降级方案） | 手动（Coze不可用时触发兜底模板） |

### 4.2 功能点

| 编号 | 功能 | 说明 |
|------|------|------|
| 10-D01 | 天气预警推送 | 高德天气API推送黄色/红色预警，听单页顶部展示预警横幅（黄色/红色） |
| 10-D02 | 路线风险提示 | 接单时根据天气+路段数据提示「前方 X 公里有积水路段，建议绕行」 |
| 10-D03 | 积水上报 | 行程中点击「上报积水」→ 拍照 → AI识别积水深度+位置 → 上报服务端 |
| 10-D04 | 智能客服降级 | Coze API不可用时 → 固定问答模板 → 展示「AI客服暂时离线，请使用人工客服」 |

### 4.3 操作流程

**天气预警推送流程**：高德天气API每15分钟获取气象数据 → 匹配预警规则（黄色/红色）→ 如当前司机所在城市有预警 → 听单页顶部显示预警横幅（黄色=黄底黑字/红色=红底白字）→ 红色预警时自动弹窗提示 + 语音播报「暴雨红色预警，请注意行车安全」→ 司机可点击查看详情（预警范围/持续时间/建议路线）。

**路线风险提示流程**：司机接单后 → 系统分析行程路线 + 当前天气 + 积水上报数据 → 如路线内有已知积水路段 → 派单页卡片底部展示提示「⚠️ 前方 X 公里处有积水路段（深度 Y cm），建议绕行 Z 路线」→ 司机可点击「查看绕行路线」→ 跳转至第三方地图APP导航绕行。

**积水上报流程**：行程中或空闲时 → 司机点击「上报积水」→ 选择拍照 → 拍摄积水照片 → AI识别积水深度（置信度展示）→ 自动关联当前GPS位置 → 确认上报 → 上报成功 + 积分奖励提示（每次上报+5分）→ 管理端收到上报数据后处理。

### 4.4 业务约束规则

| 规则类别 | 规则内容 |
|---------|---------|
| 业务规则 | 天气预警展示根据司机当前GPS所在城市判断；红色预警自动弹窗不可关闭；积水上报照片需包含水标参照物 |
| 时效规则 | 天气数据刷新间隔≥15分钟；积水上报AI识别≤3秒 |
| 降级策略 | Coze API超时5s → 降级为模板对话；连续3次降级 → 推送告警给管理端 |
| 合规要求 | 积水上报照片仅用于路线优化和市政上报，不上传至司机相册；位置数据采集需用户授权 |
| 操作红线 | 不可伪造积水上报（AI识图校验 + 同一位置5分钟内不可重复上报）|

### 4.5 权限范围

| 司机状态 | AI 助手能力 |
|---------|-----------|
| 未认证 | 仅天气预警查看（听单页横幅） |
| 已认证在岗 | 全部AI功能：天气预警/路线风险提示/积水上报 |
| 已认证离岗 | 仅查看天气预警推送 |

### 6.4 工单02 — 今日班车排班完整页面补强

| 页面区域 | 展示字段 | 操作 |
|---------|---------|------|

| 站点时序区 | 站点名称、站点序号、距首站偏移分钟、预计到站时间、上/下车类型 | 点击站点展开乘客名单；地图定位该站点 |
| 乘客与验票区 | 已购票人数、已验票人数、未验票人数、退票人数 | 扫码验票、手动验票、标记未到 |

**异常场景**：车辆故障时司机点击“异常上报”，选择故障、拥堵、天气、乘客纠纷等原因，上传照片，系统通知调度岗。临近发车前2小时内排班变更需司机确认收到；未确认时调度岗面板持续提示。

### 6.5 工单03 — 司机收入统计逐笔流水补强

**收入统计入口**：司机端「我的-收入统计」分为“收入总览、订单流水、账单确认、争议记录”四个Tab。

| Tab | 展示内容 | 关键规则 |
|-----|---------|---------|
| 收入总览 | 今日/本周/本月收入、完单数、平台抽成、退款扣减、奖励补发、预计结算金额 | 默认按完成时间统计；退款扣减实时影响预计结算 |
| 订单流水 | 订单号、订单来源、完成时间、订单金额、平台抽成、优惠券抵扣、退款扣减、司机实收、结算状态 | 支持按日期、订单来源、结算状态筛选；每笔可进入订单详情 |
| 账单确认 | 日/周/月账单、确认期限、应结算金额、已打款金额、争议状态 | 7天未确认自动确认；司机可发起账单争议 |

**逐笔流水计算**：司机实收 = 订单实付金额 - 平台抽成 - 退款扣减 + 平台奖励 + 人工补发。订单发生退款时，流水行展示“退款扣减”负数记录，并关联原订单和退款流水号；优惠券抵扣只影响乘客实付和平台营销成本，不直接减少司机合同约定收入，若活动规则要求平台承担优惠，则司机实收按原价计算。

**流水详情页**：展示订单基础信息、乘客脱敏信息、费用明细、抽成规则、退款记录、优惠券承担方、账单批次号、支付/结算流水号、操作日志。司机对单笔流水有异议时点击“发起争议”，填写原因并上传凭证，进入管理端财务争议工单。
