### **4. 前端点击流程：乘客端**

- 打开乘客端，进入登录页
- 输入手机号，获取验证码
- 登录成功后进入首页
- 首页点击“发布需求”，填写起点、终点、时间、座位数并提交
- 首页点击“行程列表”，能搜索/查看行程详情
- 行程详情点击下单，生成订单
- 我的订单能看到订单列表
- 订单详情能查看状态
- 订单详情/追踪页能查看司机轨迹
- AI 助手页面输入问题，能返回 Coze 结果
- 暴雨路线页面输入起终点，能返回路线建议
- 积水上报页面提交城市、位置、水深、置信度，后台能看到

### **7. 链路闭环**

- 司机发布行程 -> 乘客搜索到行程
- 乘客下单 -> 司机待接单出现订单
- 司机接单 -> 乘客订单状态更新
- 司机上报位置 -> 乘客轨迹页可见
- 乘客积水上报 -> 管理端 AI 水情列表可见
- 管理端审核水情 -> 司机端 AI 预警可见
- 乘客 AI 问答 -> gateway 调 Coze -> 返回结果
- Coze 调 TRAVEL_API_BASE_URL/api/travel/route-info-> gateway 返回路线基础信息

### **8. 异常流程**

- 未登录访问受保护接口，应返回未授权
- 无权限访问后台接口，应返回无权限
- 乘客查看别人的订单，应失败或无数据
- 司机修改别人的车辆，应失败
- 司机查看别人的轨迹，应失败
- 下单座位数超过余座，应失败
- 重复接单/已取消订单接单，应失败
- AI token 缺失时，接口不能崩溃，应返回明确错误或降级
- Coze 不可用时，管理端/移动端应能看到失败提示或降级文案
- cpolar 地址失效时，Coze 回调失败，但本地 gateway 不应崩溃
- 参数缺失，例如 origin/destination/city 为空，应返回校验错误
- 积水置信度小于阈值，应进入人工审核
- 积水置信度高于阈值，应自动确认或进入预期状态
