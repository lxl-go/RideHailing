## 一、顺风车管理模块

### 1. 功能页面布局

页面采用左右分栏布局。左侧为筛选区，包含注册状态（待审核/已通过/已驳回）、注册时间范围、手机号精确搜索、身份证号精确搜索。右侧为主列表区，采用分页表格展示，核心列：注册时间、真实姓名、手机号、身份证号、证件状态（已上传/未上传/审核中）、车辆绑定状态、注册来源（乘客/司机）、操作。每行提供「审核」「详情」「禁用」三个按钮。顶部右侧悬浮「批量审核」「批量导出」「配置管理」入口。配置管理页面为模态窗，包含：车辆年检提醒阈值（天）、保险到期提醒阈值（天）、紧急求助默认联系人、保险覆盖说明富文本编辑器。

### 2. 功能点

| 编号 | 功能 | 说明 |
|------|------|------|
| 01-F01 | 实名注册审核 | 乘客/司机提交实名信息后，管理端审核身份证正反面、人像比对结果；支持通过/驳回（填驳回原因） |
| 01-F02 | 身份验证管理 | 司机额外校验驾驶证有效期、准驾车型；系统自动OCR识别证件信息填入表单 |
| 01-F03 | 行程发布管理 | 查看全部行程列表；支持按起点/终点/发布时间/行程状态筛选；可人工下架违规行程 |
| 01-F04 | 行程搜索 | 乘客端发布的行程在管理端实时可见；支持全文检索起点/终点关键词 |
| 01-F05 | 紧急求助记录 | 查看所有紧急求助工单列表，含求助时间、用户信息、GPS坐标、处理状态；支持标记已处理 |
| 01-F06 | 行程分享记录 | 查看行程分享的链接访问统计数据（分享次数、打开次数） |
| 01-F07 | 保险覆盖配置 | 后台配置保险说明文案（富文本）、保险金额、理赔电话；生效范围可指定线路/区域 |
| 01-F08 | 双向评价管理 | 查看乘客对司机、司机对乘客的全部评价；支持回复、隐藏不当评价、统计评价分数分布 |
| 01-F09 | 顺风车司机配置 | 司机基础信息编辑、车辆信息（品牌/型号/颜色/车牌/年检日期/保险到期日）编辑、证件到期提醒设置 |
| 01-F10 | 操作日志 | 本模块所有审核、配置修改、行程下架等操作均记录操作人、操作时间、操作内容、IP地址 |

### 3. 操作流程

#### 正常操作流程

实名注册审核流程：乘客/司机提交注册 → 管理端收到待审核条目（列表页状态「待审核」）→ 管理员点击「详情」查看证件照片与OCR提取信息 → 核对无误后点击「通过」→ 系统发送短信/APP推送通知用户审核通过 → 状态变更为「已通过」→ 用户可正常使用顺风车功能。

行程下架流程：管理员在行程列表找到违规行程 → 点击「下架」→ 弹出确认弹窗填写下架原因（必填）→ 确认后行程状态变更为「已下架」→ 系统推送通知给发布者 → 行程不再在乘客端/司机端展示。

#### 异常操作流程

- 证件照片模糊/不完整：管理员点击「驳回」→ 选择驳回模板（照片不清晰/证件不完整/信息不一致）或手动输入原因 → 用户端收到驳回通知+修改指引 → 用户重新上传后进入二次审核队列
- 重复注册：系统检测到同一身份证号/手机号已注册 → 页面高亮提示「疑似重复」→ 管理员可查看两个账号的注册时间/IP → 合并或禁用冗余账号
- 紧急求助超时未处理：求助工单超过30分钟未标记处理 → 系统自动升级通知到超级管理员 → 超60分钟触发短信报警
- 保险配置生效冲突：新增保险范围与已有范围重叠 → 系统弹窗提示「与XX线路保险配置重叠，是否覆盖？」→ 确认覆盖则历史数据仍保留旧配置

### 4. 业务流程

用户注册（乘客/司机）→ 提交实名信息+证件照片 → 系统OCR自动提取+初步校验 → 进入管理端审核队列 → 管理员审核 → 通过则激活账号 → 不通过则退回修改。审核通过后司机可发布行程、乘客可发布行程。行程发布后匹配乘客/司机 → 完成行程 → 触发双向评价 → 评价数据进入统计报表。行程中用户可发起紧急求助 → 求助工单推送至管理端 + 同步推送预设紧急联系人 → 处理完毕后关闭工单。所有审核、下架、配置变更均记入操作日志。

### 5. 业务约束规则

| 规则类别 | 规则内容 |
|---------|---------|
| 业务规则 | 司机必须完成实名认证+车辆绑定才能发布行程；乘客完成实名认证才能预约行程 |
| 时效规则 | 审核超48小时未处理自动升级提醒；紧急求助30分钟未处理升级 |
| 合规要求 | 证件信息存储加密（AES-256）；删除操作软删除保留180天 |
| 性能约束 | 列表分页每页20条；行程搜索响应≤1s |
| 数据规则 | 同一手机号+身份证号唯一注册；证件OCR准确率≥95% |
| 操作红线 | 审核操作不可撤回，误操作需通过「申诉」流程由超级管理员处理 |

### 6. 权限范围

| 角色 | 可操作范围 |
|------|-----------|
| 超级管理员 | 全部功能，含配置管理、审核、下架、日志查看、驳回模板编辑 |
| 班车运营岗 | 行程查看、评价查看（不可下架行程，不可修改配置） |
| 调度岗 | 紧急求助处理、行程信息查看 |
| 财务岗 | 无权限（模块不可见） |
| 营销岗 | 无权限 |
| 数据岗 | 评价统计查看、注册统计查看（只读） |
| 验票员 | 无权限 |

## 二、班车管理模块

### 1. 功能页面布局

主页面采用三栏Tab布局。Tab一「班线管理」：左侧树形区域展示公司/分公司/车队层级结构，点击节点右侧展示该层级下的班线列表（表格形式，列：线路名称、起点-终点、里程(km)、时长(min)、状态、操作），点击班线名称进入班线详情页。Tab二「排班管理」：顶部日期选择器（日历组件，支持多选日期范围）+ 班线下拉选择，中部甘特图/时间轴展示选定日期内所有班次的司机排班情况，支持拖拽调整。Tab三「站点管理」：大地图区域嵌入页面左侧（占比60%），右侧为站点列表（表格：站点名称、类型、经纬度、偏移时间(min)、所属线路），地图上标注所有站点并连线形成路线。

班线详情页布局：头部信息区（线路名称/起点终点/里程/时长/状态）+ 站点列表（拖拽排序+偏移时间编辑）+ 线路地图（标注站点+自动连线）+ 关联班次列表（日期/发车时间/到达时间/票价/余票）。

### 2. 功能点

| 编号 | 功能 | 说明 |
|------|------|------|
| 02-F01 | 班线创建 | 填写线路名称、起点/终点名称、里程、预计时长、描述，选择所属分公司 |
| 02-F02 | 班线编辑 | 修改班线基础信息，已发布班线编辑后需重新确认生效 |
| 02-F03 | 班线启用/停用 | 停用后乘客端不可预约，不影响历史数据 |
| 02-F04 | 班次管理 | 设置发车时间、到达时间、票价、余票上限；关联所属班线 |
| 02-F05 | 排班管理（司机） | 选择日期+班次 → 选择司机 → 时间窗冲突校验 → 保存 |
| 02-F06 | 排班管理（车辆） | 选择日期+班次 → 选择车辆 → 容量匹配校验 → 保存 |
| 02-F07 | 排班管理（日期） | 批量选择日期范围 → 一键复制排班模板 → 快速排班 |
| 02-F08 | 站点管理 | 添加/编辑/删除站点（名称、类型、经纬度、偏移时间） |
| 02-F09 | 站点排序 | 按偏移时间自动升序排列 + 拖拽手动调整 |
| 02-F10 | 站点排重 | 自动校验同一站点不可同时为上车点和下车点 |
| 02-F11 | 线路地图 | 地图展示所有站点+行驶路线连线+实时路况 |
| 02-F12 | 排班冲突校验 | 校验同一司机的排班时间窗重叠、车辆预约冲突 |
| 02-F13 | 运营数据报表 | 按班线/日期维度的上座率、准点率、收入统计 |

### 3. 操作流程

#### 正常操作流程

班线创建流程：管理员点击「新建班线」→ 填写线路名称、起点名称、终点名称、线路总里程(km)、预计总时长(min)、线路描述 → 选择所属分公司/车队 → 保存后班线进入「已启用」状态 → 进入「站点管理」添加站点。

站点添加与排序流程：在班线详情页点击「添加站点」→ 输入站点名称、位置（地图选点/手动输入经纬度）、站点类型（上车点/下车点/综合点）、预计到达时间（相对首站偏移分钟数）→ 系统自动按偏移时间升序排列站点列表 → 支持拖拽调整顺序 → 首站偏移时间固定为0 → 保存后验证「同一站点不可同时为上车点和下车点」。

排班管理流程：进入「排班管理」→ 选择日期范围 → 选择班线 → 系统展示该班线当天的所有班次 → 点击「添加排班」→ 选择可用司机（下拉列表含司机姓名+电话+空闲状态）、选择可用车辆（车牌号+车型）→ 系统自动校验该司机当天其他排班的时间窗冲突 → 校验通过后保存 → 该班次关联司机和车辆。

#### 异常操作流程

- 站点排重冲突：添加站点时系统检测到该站点已在本班线的上车点和下车点同时出现 → 弹窗提示「站点XX已配置为上车点，不能同时设为下车点」→ 禁止保存
- 排班时间冲突：选择的司机在所选时间窗内已有其他排班 → 红色高亮提示「司机XX在08:00-09:30已有班次XX」→ 建议可选「强制排班」或「重新选择司机」→ 强制排班需填写理由
- 司机车辆不匹配：车辆准载人数与该班线预设人数不匹配 → 弹窗预警「建议更换车辆」
- 班线删除保护：班线已有历史运营数据时 → 提示「该班线已有XX条运营记录，删除后将归档，不可恢复」

### 4. 业务流程

公司开通班线 → 配置班线基础信息 → 添加站点并设置偏移时间 → 系统自动排序 → 验证站点唯一性 → 发布班线 → 排班员选择日期+班线+班次 → 匹配司机（时间窗校验）→ 匹配车辆（容量校验）→ 保存排班 → 排班数据推送至乘客端（展示班次时间+站点）和司机端（展示今日排班+路线）→ 运营结束后生成运营数据报表。

站点排序逻辑：上车站点偏移时间由小到大排列，下车站点同样按偏移时间排序。若上车站点到达时间为 T1, T2, T3...Ti，下车站点到达时间为 Ti+1, Ti+2...Tn，则完整的时序列表为 T1→T2→...→Tn，每个站点在前一站的基础上累加行程时长。

### 5. 业务约束规则

| 规则类别 | 规则内容 |
|---------|---------|
| 业务规则 | 同一班线内，同一站点不可同时为上车点和下车点；站点按偏移时间自动升序排列，首站偏移时间=0 |
| 时效规则 | 排班变更需在发车前2小时完成，临近发车禁止修改 |
| 合规要求 | 司机每日累计驾驶时长≤8小时，连续驾驶≥4小时需强制休息20分钟 |
| 性能约束 | 地图加载响应≤3s；排班冲突校验响应≤1s；关键接口需Jmeter压测验证 |
| 数据规则 | 站点经纬度精度到6位小数；排班数据不可覆盖仅可撤销后重建 |
| 删除引用校验 | 班线删除前检查是否有关联未完成的排班 → 有则禁止删除，提示「该班线有 N 个未完成的排班，请先处理」；站点删除前检查是否被班线引用 → 有则提示「该站点被 N 条班线引用，请先解除关联」 |
| 操作红线 | 排班错误导致司机漏班，按运营事故处理 |

### 6. 权限范围

| 角色 | 可操作范围 |
|------|-----------|
| 超级管理员 | 全部功能，含班线/班次/排班/站点/地图配置 |
| 班车运营岗 | 班线创建/编辑、站点管理、班次管理（排班除外） |
| 调度岗 | 排班管理、司机/车辆排班分配、排班冲突调整 |
| 财务岗 | 线路里程、时长数据查看（用于结算） |
| 营销岗 | 无权限 |
| 数据岗 | 运营报表查看（只读） |
| 验票员 | 班次时刻表查看、站点信息查看 |

## 三、财务管理模块

### 1. 功能页面布局

页面采用Tab页切换布局。Tab一「收支对账」：顶部日期范围选择器 + 支付方式下拉筛选（全部/信用卡/电子钱包/银行转账/余额） + 对账状态筛选（已对平/待处理/差异），中部双表格布局（上半部分为系统交易流水表，下半部分为支付平台对账流水表），底部为差异汇总卡片（总笔数/匹配成功/差异笔数/差异金额）。Tab二「账单管理」：顶部切换双端账单（司机端/乘客端） + 账单周期选择（日/周/月） + 时间范围，列表展示（账单编号/用户名/周期/总收入/总支出/状态），点击进入账单详情。Tab三「异常处理」：异常交易列表（异常类型/订单号/金额/触发时间/处理状态），每行提供「处理」按钮。Tab四「争议工单」：工单列表（工单编号/类型/关联订单/金额/状态/创建时间/优先级），支持按状态筛选。

### 2. 功能点

| 编号 | 功能 | 说明 |
|------|------|------|
| 03-F01 | 收支对账表 | 展示每日交易流水明细：日期、订单号、金额、支付方式、交易状态 |
| 03-F02 | 对账匹配 | 系统流水 vs 支付平台流水逐笔自动匹配，支持人工干预 |
| 03-F03 | 自动账单生成 | 日/周/月账单，按司机和乘客双维度自动汇总生成 |
| 03-F04 | 双端账单核对 | 司机端/乘客端各自查看自己的账单，7天确认期自动确认 |
| 03-F05 | 异常交易检测 | 重复扣款、金额不符、缺失交易自动识别并标记 |
| 03-F06 | 争议工单管理 | 创建/处理/关闭争议工单，支持附件上传、审批流转 |
| 03-F07 | 线路结算表 | 按线路维度汇总收入和成本，支持导出 |
| 03-F08 | 支付方式管理 | 配置支持支付的渠道，设置各渠道手续费率 |
| 03-F09 | 退款处理 | 自动/手动退款发起，退款状态跟踪 |
| 03-F10 | 财务统计报表 | 月度/季度/年度财务报表，支持图表展示和导出 |

### 3. 操作流程

#### 正常操作流程

自动对账流程：系统每日凌晨02:00触发对账任务 → 拉取支付平台前一日交易流水 → 与本系统订单支付记录逐笔匹配 → 匹配成功则标记「已对平」→ 匹配失败则标记「待处理」→ 生成对账差异报告 → 推送给财务岗。

自动账单生成流程：每月1日00:00系统触发月账单生成 → 按司机维度汇总上月订单流水 → 计算总收入（订单金额-平台抽成）→ 生成司机对账单 → 同时按乘客维度生成消费账单 → 双端账单状态均为「待确认」→ 司机/乘客可在各自端查看 → 7天内无异议自动确认。

争议处理流程：财务岗在异常列表点击「创建争议工单」→ 填写争议类型（重复扣款/金额不符/未收到退款/其他）、关联订单号、金额、说明 → 提交 → 争议工单进入「待处理」状态 → 系统派发给对应审核人员 → 审核人员查看交易流水 → 判定归属 → 若为系统错误则发起退款/补发 → 若为用户误解则附说明关闭工单。

#### 异常操作流程

- 对账差异无法自动匹配：差异条目标红 → 财务岗逐条人工核对 → 支持选择「以支付平台为准」「以系统为准」「人工调整」三种处理方式 → 处理后记录操作日志
- 司机对账单争议：司机在司机端发起对账异议 → 管理端收到争议标记 → 财务岗查看司机账单明细 → 如有误则手动修正 → 修正后重新生成账单
- 重复扣款检测：同一订单号在支付平台出现多笔扣款 → 系统自动识别 → 创建退款工单 → 自动发起退款 → 通知用户
- 退款失败：退款接口返回失败 → 系统自动重试3次（间隔5分钟）→ 仍失败则生成人工处理工单 → 财务岗手动处理

### 4. 业务流程

订单完成 → 支付成功 → 交易数据写入流水表 → 每日凌晨对账任务执行 → 支付平台流水 vs 系统订单逐笔匹配 → 对平则归档 → 差异则进异常队列 → 财务岗处理。每月账单日 → 按司机汇总收入 → 按乘客汇总支出 → 生成账单 → 双端推送 → 7日确认期 → 确认后归档。司机/乘客发起争议 → 争议工单创建 → 审核 → 结果判定 → 退款/驳回 → 更新账单 → 关闭工单。线路结算按线路维度独立汇总收入和成本。

### 5. 业务约束规则

| 规则类别 | 规则内容 |
|---------|---------|
| 业务规则 | 账单以司机实际完单量为准；平台抽成比例按合同约定执行；退款优先原路返回 |
| 时效规则 | 每日对账在凌晨02:00-04:00完成；司机账单7日确认期，超时自动确认；退款处理T+1到账 |
| 合规要求 | 资金流水保存≥5年；对账差异超5%需人工复核；退款需审批流（单笔≥500元需二级审批） |
| 性能约束 | 对账任务30分钟内完成（日均10万条以内）；流水查询QPS≥500 |
| 数据规则 | 金额字段精度到分（两位小数）；支付方式枚举值（信用卡/电子钱包/银行转账/余额） |
| 操作红线 | 人工调整对账差异必须双人复核；退款金额不可超过原订单金额 |

### 3. 操作流程

#### 正常操作流程

订单筛选查看流程：进入订单列表页 → 选择订单来源（班车/顺风车）→ 选择订单状态（待支付/已支付/进行中/已完成/已取消/已退款）→ 选择创建时间范围 → 输入车牌号/乘客手机号关键字 → 点击「查询」→ 列表展示符合条件订单 → 点击某行进入订单详情页。

退票审核流程（自动）：乘客在乘客端发起退票申请 → 系统自动校验是否满足自动审核条件（退票时间距发车>2小时、无违规记录、订单金额≤500元）→ 条件满足则自动通过 → 原路退款 → 订单状态变更为「已退款」。

退票审核流程（人工）：乘客发起退票申请但不符合自动审核条件 → 进入人工审核队列 → 管理员在退票管理列表看到「待审核」标记 → 点击详情查看退票原因、订单信息 → 选择「通过」或「拒绝」 → 通过则触发退款流程 → 拒绝则填写拒绝原因回传给乘客。

批量退票流程：管理员勾选多条待退票订单（支持全选/反选）→ 点击「批量退票」→ 系统弹窗显示选中订单数量+总退款金额 → 确认后逐条执行退票 → 处理完成后生成批量退票报告（成功/失败明细）。

**批量退票手续费规则**：
- 距出发时间 > 48 小时：免费退票，全额退款
- 距出发时间 24-48 小时：收取票价 10% 手续费
- 距出发时间 2-24 小时：收取票价 30% 手续费
- 距出发时间 < 2 小时：收取票价 50% 手续费
- 已发车 / 已完成：不可退票
- 批量退票时每单独立计算手续费，汇总展示「退款总金额 = 订单总金额 - ∑单笔手续费」
- 批量退票处理报告包含每单的手续费明细

#### 异常操作流程

- 退票审核超时：退票申请超过24小时未审核 → 系统自动升级提醒 → 超48小时自动通过并退款
- 退款金额计算争议：系统根据取消费政策计算退票金额 → 乘客对计算结果有异议 → 提交客服工单 → 人工核查后手动调整
- 批量退票部分失败：批量退票执行中某条退款失败 → 系统跳过失败条目继续处理剩余 → 生成报告标记失败条目及原因 → 管理员可单独重试失败条目
- 订单状态不一致：订单在司机端显示「已完成」但在管理端显示「进行中」→ 触发状态修复任务 → 比对GPS轨迹终点时间戳 + 乘客端确认状态 → 自动修正 → 记录修正日志

### 4. 业务流程

乘客下单 → 系统生成唯一订单编号 → 订单进入派单引擎 → 司机接单 → 行程开始 → 行程完成 → 乘客支付 → 订单状态变更为「已完成」。乘客可在此过程中或完成后发起退票 → 自动审核规则校验 → 通过则直接退款 → 不通过则进入人工队列 → 审核通过后退款 → 退款计算按取消费政策执行。管理员可在订单列表查看全部订单 → 支持组合条件筛选 → 订单详情展示完整生命周期。评价在订单完成后触发 → 乘客评司机 → 司机评乘客 → 评价进入管理端评价管理模块。

取消费政策：按距发车时间区间计算扣款比例：发车前≥2小时免费取消；1~2小时扣20%；30分钟~1小时扣50%；<30分钟扣80%；发车后取消扣100%。

### 5. 业务约束规则

| 时效规则 | 退票申请距发车<30分钟仍需人工审核；退款到账T+1（支付平台同步延迟不超24h） |

| 操作红线 | 不可手动修改已完成订单的金额；批量退票操作需二次确认弹窗 |

批量操作流程：在人员列表勾选多条记录 → 点击「批量启用/禁用」→ 确认弹窗 → 系统批量修改状态 → 记录操作日志。点击「批量删除」→ 强确认弹窗（输入「确认删除」+ 操作人密码）→ 软删除（标记已删除，非物理删除）。

- 批量禁用冲突：禁用某司机时该司机有进行中的排班 → 弹窗提示「该司机有未完成的排班（班次ID：×××），确认禁用后将自动取消排班」→ 确认后解除排班并禁用
- 多角色权限冲突：某用户同时拥有调度员和财务岗角色 → 权限取并集 → 页面展示两个角色的权限标签 → 高风险操作（如退款）仍需财务岗独立权限校验

## 六、数据分析模块

### 1. 功能页面布局

页面采用顶部看板+下部分析Tab布局。顶部为KPI卡片行（今日订单量/本月订单量/本月营收/活跃司机数/活跃乘客数），支持用户自定义配置展示指标。下方为Tab切换页：Tab一「订单量分析」：图表区域（折线图+柱状图双轴联动），左侧控制面板（统计周期/时间范围/订单来源/分组维度），右侧数据明细表。Tab二「用户转化分析」：漏斗图（注册→认证→首单→支付→复购每层转化率），控制面板（时间范围/用户来源渠道/用户分层）。Tab三「复购分析」：散点图+周期分布直方图，控制面板（订单类型/用户地域/用户来源/分析周期）。Tab四「用户行为追踪」：事件列表（事件名称/触发次数/独立用户数/人均触发次数），支持按事件类型筛选。所有图表支持鼠标悬停数值提示、图表下载PNG、数据下载CSV。

### 3. 操作流程

#### 正常操作流程

订单量分析查看流程：进入「订单量分析」→ 选择统计周期（日/周/月/季度/年）→ 选择时间范围 → 选择订单来源（全部/班车/顺风车）→ 页面展示折线图（每日订单量趋势）+ 柱状图（对比周期）+ 数据表格（日期/订单数/环比/同比）→ 鼠标悬停展示具体数值 → 支持图表下载PNG/数据下载CSV。

用户转化率查看流程：进入「用户转化率分析」→ 选择时间范围 → 系统自动展示转化漏斗（注册用户数 → 完成实名认证数 → 首次下单数 → 完成支付数 → 复购数）→ 每层展示转化率+相对于首层的整体转化率 → 支持按用户来源渠道筛选。

复购周期分析流程：进入「复购分析」→ 选择分析维度（订单类型/用户地域/用户来源）→ 系统展示散点图（首次下单时间 vs 复购时间）+ 周期分布直方图（7天内/14天内/30天内/60天内/60天+）→ 展示平均复购周期、复购率（复购用户数/首次下单用户数）。

#### 异常操作流程

- 数据加载超时：统计周期跨度过大（如年度+季度对比）导致响应超5s → 提示「数据量较大，正在后台生成，请稍后刷新查看」→ 异步任务生成后推送通知
- 数据源异常：数据库连接失败 → 展示缓存中最近一期的历史数据 + 灰色提示条「数据更新于 XX 分钟前，部分数据可能延迟」
- 点击流数据缺失：用户行为追踪数据不完整 → 转化率页面提示「当前时间段行为数据覆盖率为XX%，数据仅供参考」

### 4. 业务流程

业务数据库（MySQL）→ 定时ETL任务（每日凌晨汇总）→ 写入统计宽表（日/周/月/季度/年聚合）→ 数据缓存至Redis（热门查询维度）→ 前端请求 → 优先查缓存 → 缓存miss查宽表 → 返回统计结果。用户行为数据从乘客端/司机端采集（埋点）→ 写入用户行为日志表 → 每日汇总转化漏斗。复购数据从订单表按用户ID groupby计算首次下单时间与后续下单时间间隔。

### 5. 业务约束规则

| 规则类别 | 规则内容 |
|---------|---------|
| 业务规则 | 转化率 = (产生购买行为的客户人数 ÷ 所有注册APP人数) × 100%；无效订单不计入订单量统计 |
| 时效规则 | 汇总数据T+1（今日数据明日可见）；实时数据看板可配置刷新间隔（默认5分钟） |
| 合规要求 | 用户行为数据脱敏展示；不可导出含个人身份信息的原始数据 |
| 性能约束 | 界面响应≤5s（含图表渲染）；大数据量场景异步加载；缓存命中率≥70% |
| 数据规则 | 统计口径统一（自然日/自然周/自然月）；优惠券订单单独标记统计 |
| 操作红线 | 数据分析模块全部只读，不可修改源数据 |

### 3. 操作流程

#### 正常操作流程

创建优惠券流程：进入「优惠券管理」→ 点击「新建优惠券」→ 选择类型（折扣券/现金券/免费乘车券）→ 填写面额（折扣券填折扣率如8折、现金券填固定金额如¥10、免费券自动填充为0）→ 设置使用门槛（最低消费金额）→ 设置适用范围（指定城市/区域/时间段/车辆类型/线路）→ 设置有效期（固定时间段/领取后N天有效）→ 设置库存总量 → 设置每人限领次数 → 保存。

自动发放规则配置流程：进入「发放规则」→ 点击「新建规则」→ 选择触发类型（注册成功/首次下单/累计消费额达标/用户生日/邀请好友成功）→ 选择对应的优惠券模板 → 设置发放数量 → 保存 → 当用户满足触发条件时系统自动发放。

推广活动管理流程：进入「活动管理」→ 点击「新建活动」→ 填写活动名称、活动描述 → 选择活动类型（新客立减/限时秒杀/好友助力/分享有礼）→ 选择关联的优惠券 → 设置活动时间范围 → 设置活动预算上限 → 保存 → 活动自动按配置执行。

#### 异常操作流程

- 优惠券库存不足：用户领券时库存为0 → 系统返回「已领完」→ 营销岗在后台看到该券已无库存 → 可选择「补充库存」或「下架该券」
- 适用范围冲突：某用户同时满足两条自动发放规则 → 优先执行优先级高的规则（优先级手动设置）→ 同优先级则都发放
- 活动预算超支：活动实际发放金额达到预算上限的90% → 系统发送预警通知 → 达到100%自动停止发放 → 已发放的优惠券正常使用
- 优惠券使用与退款冲突：用户使用优惠券的订单发生退款 → 按比例退回优惠券（实际支付部分按比例计算）或优惠券作废（根据退款政策配置）

### 4. 业务流程

营销岗创建优惠券模板 → 配置基本信息+适用范围 → 保存 → 配置发放规则（自动/手动）→ 自动规则绑定优惠券和触发条件 → 用户行为触发 → 系统发放优惠券 → 用户获得优惠券 → 下单时使用 → 订单完成后核销。推广活动：创建活动 → 关联优惠券 → 设置时间+预算 → 上线 → 用户参与 → 发放优惠券 → 活动数据实时统计 → 活动结束后出报告。

推荐奖励流程：用户A分享推荐链接 → 用户B通过链接注册并完成首单 → 触发推荐奖励规则 → 用户A获得奖励券 → 用户B获得新人券 → 双方券自动发放。

### 5. 业务约束规则

| 规则类别 | 规则内容 |
|---------|---------|
| 业务规则 | 优惠券不可叠加使用（每次限用1张）；折扣券和现金券不可同时使用；免费乘车券仅限指定线路 |
| 时效规则 | 优惠券有效期最长180天；活动预算达到上限自动停止，不可超发 |
| 合规要求 | 营销活动需符合《反不正当竞争法》；优惠券使用条件需在领取页明确展示 |
| 性能约束 | 优惠券列表响应≤200ms；发放接口QPS≥1000；使用缓存+索引优化；RESTful API设计 |
| 数据规则 | 同一用户对同类型优惠券限领次数按规则配置；优惠券核销后状态不可逆 |
| 操作红线 | 不可手工创建无库存上限的优惠券（防止无限发放风险）；优惠券模板发布后不可修改面额 |

### 3. 操作流程

#### 正常操作流程

订单组合搜索流程：进入「订单中心」→ 展开筛选面板 → 选择订单来源（系统派单/手动创建）、订单状态（待接单/已接单/进行中/已完成/已取消/已改派）、创建时间范围、车牌号（模糊搜索）→ 点击「查询」→ 列表展示结果支持按创建时间/金额/距离排序 → 支持分页。

订单详情查看流程：在订单列表点击某行 → 进入详情页 → 页面分为：①基础信息区（订单编号/状态/来源/创建时间/完成时间）、②乘客信息区（姓名/手机号（脱敏）/常用地址）、③费用明细区（里程费/时长费/远途费/夜间费/优惠抵扣/实付金额）、④状态变更时间线（每一状态变更的时间戳+操作人+变更前状态→变更后状态）、⑤风控标记区（异常码/风控等级/风控备注）。

派单规则配置流程：进入「派单设置」→ 规则a配置（优先分配策略：用车时间先后/乘客等级/订单金额高低）→ 规则b配置（司机冲突校验：同一时间窗最大接单数/最小空闲间隔）→ 规则c配置（时段权重：白天时段各因子权重值、夜间时段各因子权重值、超时未分配策略：逐步扩大搜索半径或降级规则）→ 规则d配置（候选司机池：按城市/车队/热区/动态分组筛选，支持多条件组合）→ 保存 → 可发布到灰度环境（指定比例流量验证）→ 验证通过后全量发布。

#### 异常操作流程

- 订单改派（智能重算）：管理员发起改派 → 系统锁定当前订单 → 通知原司机「订单已被改派」→ 触发派单引擎重算 → 按当前规则重新匹配司机 → 匹配成功后通知新司机 → 订单状态变更为「已改派」
- 订单取消失败：取消请求因订单状态异常被系统拒绝 → 管理员可强制取消（填写原因+操作人密码）→ 强制取消记录审计
- 派单引擎无合适司机：按默认规则+扩大半径后仍无司机 → 系统提示「暂无可用司机」→ 进入等待队列 → 有可用司机时自动再次尝试匹配 → 超时15分钟系统通知乘客
- 灰度发布故障：灰度期间收到负面反馈或监控指标异常 → 管理员一键回滚至上一版本 → 回滚后灰度流量切回旧规则 → 记录回滚事件

### 4. 业务流程

用户下单 → 订单创建（幂等键去重）→ 订单写入MySQL + 缓存到Redis → 触发派单引擎 → 规则a筛选候选池（按时间/优先级排序）→ 规则b校验时间窗冲突 → 规则c计算时段权重 → 规则d确定司机池范围 → 多维评分（GEO距离×权重1 + 司机评分×权重2 + 时间窗罚分×权重3 + 历史接单率×权重4）→ 评分排序 → 派给最优司机 → 司机端收到派单 → 司机接单/拒绝 → 接单成功则推送乘客 → 订单状态流转（待接单→已接单→司机已到达→行程中→已完成）→ WebSocket实时推送位置给乘客。订单同步写操作审计日志。

### 5. 业务约束规则

| 规则类别 | 规则内容 |
|---------|---------|
| 业务规则 | 派单规则a：按用车时间先后优先分配；规则b：校验司机时间窗内无冲突+可服务；规则c：白天(7:00-22:00)与夜间不同权重/超时策略；规则d：候选司机池按城市/车队/热区/分组动态调整 |
| 时效规则 | 派单响应目标≤3s；WebSocket心跳间隔30s，断线重连60s超时；超时15分钟无司机→通知乘客 |
| 合规要求 | 派单决策理由可审计可解释；灰度发布必须可控流量比例（5%/20%/50%/100%）+一条回滚路径 |
| 性能约束 | 派单引擎无重复分配无竞态（Redis分布式锁）；缓存命中率≥70%；只读副本+二级缓存 |
| 数据规则 | 订单状态变更通过状态机严格约束（每个状态有明确的入度/出度）；轨迹数据热冷分层（Redis热存7天+MySQL冷存30天+归档） |
| 操作红线 | 不可直接修改线上派单规则（必须走灰度→全量发布流程）；改派操作需记录原司机+新司机+改派人+原因+时间戳 |

## 十二、模块之间的链路闭环

### 12.1 数据流转总览

核心模块并非孤立系统，而是通过统一的数据中台形成闭环。核心数据实体及其流转关系如下：

**订单数据**是所有模块的中枢神经：
- 订单管理模块产生/维护订单主数据
- 订单中心与派单模块负责订单的创建、匹配、状态流转
- 财务管理模块消费订单的支付和退款数据生成账务记录
- 数据分析模块消费订单的维度和指标进行统计建模
- 营销管理模块消费订单的优惠券核销数据、评估活动效果

**人员数据**是权限和业务执行的基础：
- 人员管理模块定义角色和权限（AuthMiddleware + TableName 策略）
- 班车管理的排班功能消费司机数据和车辆数据
- 订单派单的候选司机池来源于人员管理中的司机数据
- 财务管理的对账单按司机维度和乘客维度编制

**配置数据**驱动各模块的业务规则：
- 顺风车管理的保险配置、审核规则
- 班车管理的班线/站点/排班配置
- 财务管理的对账规则、结算比例
- 订单管理的取消费政策
- 营销管理的优惠券规则、活动配置
- 派单引擎的规则a/b/c/d参数

### 9.2 端到端全链路业务闭环示例

以"乘客预约班车→支付→乘车→评价→对账"的完整链路为例：

```
[乘客端] 乘客下单 → 生成订单（订单中心）
    ↓
[订单中心] 订单状态：待支付
    ↓
[乘客端] 乘客支付 → 回调通知订单中心 → 订单状态变更为「已支付」
    ↓
[乘客端/司机端] 发车当日 → 司机端查看排班（数据来源：班车管理排班模块）
    ↓
[司机端] 司机确认发车 → 乘客端收到上车提醒 → 司机到达站点 → 乘客扫码/验票上车
    ↓
[验票员] 验票确认（验票员端/管理端验票模块）
    ↓
[司机端] 行程完成 → 订单状态变更为「已完成」
    ↓
[乘客端/司机端] 触发双向评价 → 评价数据写入评价管理（订单管理模块）
    ↓
[管理端] 订单详情页可查看完整评价
    ↓
[财务管理] 每日凌晨对账 → 该笔订单的支付流水与系统记录自动匹配
    ↓
[财务管理] 月账单生成 → 该笔收入进入司机对账单 + 乘客消费账单
    ↓
[数据分析] 该笔订单进入统计宽表 → 更新订单量/转化率/复购周期等指标
```

### 9.3 跨模块依赖关系矩阵

| 模块 | 依赖上游 | 产出数据 | 下游消费方 |
|------|---------|---------|-----------|
| 顺风车管理 | 人员管理（司机/乘客） | 认证数据、评价数据 | 数据分析 |
| 班车管理 | 人员管理（司机） | 班线/排班数据 | 订单中心、乘客端/司机端 |
| 财务管理 | 订单管理、支付平台 | 对账数据、账单、争议工单 | 数据分析 |
| 订单管理 | 人员管理、派单引擎 | 订单数据、评价数据、退票数据 | 财务管理、数据分析 |
| 人员管理 | — | 用户/角色/权限数据 | 所有模块 |
| 数据分析 | 订单管理、财务管理、营销管理 | 统计报表、趋势预测 | 管理层决策 |
| 营销管理 | 人员管理（乘客） | 优惠券、活动、推荐数据 | 订单管理（核销）、财务管理（核算） |
| 订单中心与派单 | 人员管理（司机）、订单管理 | 派单决策、订单流转、WebSocket推送 | 司机端、乘客端、财务管理 |

### 9.4 跨端联动

管理端配置的班线/站点/排班 → 数据实时同步 → 乘客端展示可预约班次 + 司机端展示今日排班路线。管理端配置的派单规则 → 派单引擎实时执行 → 司机端收到派单推送 → 乘客端收到接单确认+车辆实时位置。管理端配置的优惠券/活动 → 乘客端领取和使用 → 订单核销时自动校验优惠券规则。管理端审核司机认证 → 司机端收到审核结果通知。乘客端/司机端产生的订单和评价 → 实时回流至管理端订单列表和数据分析报表。乘客端/司机端发起的退票申请 → 管理端退票审核队列处理 → 结果回推至两端。乘客端/司机端紧急求助 → 管理端紧急求助面板实时展示 -> 调度岗处理 -> 求助状态更新。

### 9.5 数据一致性保障

- **事务边界**：订单创建使用本地事务+消息队列确保最终一致性；支付回调使用幂等键防止重复处理
- **缓存策略**：热点数据Redis缓存，MySQL为最终数据源；规则配置变更时主动失效相关缓存
- **异步对账**：依赖支付平台的财务数据采用T+1异步对账，对不平数据标记差异待人工处理
- **状态机约束**：订单状态变更严格受状态机约束，非法状态转换直接拒绝
- **操作审计**：跨模块的敏感操作统一记录审计日志，支持全链路追踪
